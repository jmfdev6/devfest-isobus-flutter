# 3D com flutter_scene

Os dois apps desenham em 3D com [flutter_scene](https://pub.dev/packages/flutter_scene) **0.24.6**, que roda sobre o **Flutter GPU**. O código compartilhado está em [`pacotes/cena`](https://github.com/jmfdev6/devfest-isobus-flutter/tree/main/pacotes/cena), com os modelos em `assets/` (`tractor.glb`, `plantadeira.glb`).

## Ligar o Flutter GPU

O Flutter GPU ainda é *opt-in*. Cada runner Linux liga a flag:

```c
// apps/<app>/linux/runner/my_application.cc
fl_dart_project_set_enable_flutter_gpu(project, TRUE);
```

Precisa do Flutter 3.47.1 ou mais novo. Para testar sem mexer no runner: `flutter run -d linux --enable-flutter-gpu`. Se o GPU não estiver disponível, a cabine mostra "3D indisponível" no lugar da plantadeira.

Os shaders são preparados uma vez só (`prepararCena()` → `Scene.initializeStaticResources()`), antes de montar qualquer cena.

## Sistema de coordenadas

```text
X = leste    Y = cima    Z = norte       (metros a partir da origem do talhão)
```

O flutter_scene usa **mão esquerda**, e o glTF usa mão direita. O `fromGlbAsset` põe o modelo importado debaixo de um **espelho em Z**, e a frente dos nossos modelos (+Z no glTF) vira −Z. A solução é um nó intermediário:

```dart
Node _virado(Node modelo) => Node(name: 'virado')
  ..rotation = Quaternion.axisAngle(Vector3(0, 1, 0), pi)  // 180° em Y
  ..add(modelo);
```

!!! warning "Não mexa no nó importado"
    O espelho mora nele. Rotação ou escala aplicadas direto ali se combinam com o espelho e invertem o sentido do giro. Transforme sempre o nó `virado` ou um pai dele.

O rumo (0 = norte, horário) vira uma rotação em Y de `rumo` graus: com X a leste e Z a norte na mão esquerda, o sentido horário visto de cima coincide.

## A plantadeira da cabine

[`cena.dart`](https://github.com/jmfdev6/devfest-isobus-flutter/blob/main/pacotes/cena/lib/cena.dart): o modelo é esticado na largura da barra, e o pote de cada linha fica **verde** (seção plantando) ou **vermelho** (cortada), como os funis do VT. Sementes caem só nas linhas das seções ligadas. O modelo tem 16 linhas (a ~0,57 m), esticadas para os 9,144 m da barra e divididas entre as 6 seções do DDOP.

## O talhão do simulador

[`talhao.dart`](https://github.com/jmfdev6/devfest-isobus-flutter/blob/main/pacotes/cena/lib/talhao.dart):

- céu físico (`PhysicalSkySource`) com sol, **sombras** e neblina (densidade 0,003, a partir de 60 m) que puxa a cor do céu. Na câmera de cima, a neblina é desligada;
- três câmeras: **cabine**, **atrás** (segue com suavização) e **de cima**;
- o trator "joga" com o solo: arfagem e rolagem proporcionais à velocidade;
- rodas dianteiras esterçam com o ângulo da física;
- a plantadeira segue o [`Engate`](tc.md#o-engate), o mesmo modelo do TC;
- a rota do piloto é um `InstancedMesh`: um cubo achatado por segmento, desenhado numa só chamada.

### O chão: uma textura

O chão do talhão é **um plano** com **uma textura** do tamanho do [mapa de aplicação](mapa-aplicacao.md) (um pixel por célula):

1. a **cor de base** (terra com manchas de ruído, levemente mais escura onde a prescrição é maior; carreador fora do contorno) é calculada num **isolate**, sem travar a interface;
2. cada célula plantada pinta **um pixel** (`TcAutomatico.aoPlantar` → índice da célula), na cor do modo atual (terra revolvida, taxa, prescrito × aplicado);
3. a textura sobe para a GPU com `gpuTexture.overwrite` **no máximo a cada ~150 ms**, e só se mudou.

!!! note "Por que não uma peça 3D por célula"
    A primeira versão punha um cubo instanciado por célula plantada. Cada célula nova reenviava todas as instâncias à GPU: custo O(n²) na área plantada, e o simulador travava depois de alguns hectares. Com a textura, plantar custa O(1) por célula e o envio é limitado no tempo.

## Desempenho

| Medida | Efeito |
|---|---|
| textura em vez de instâncias | custo constante por célula |
| *throttle* de 150 ms no envio | no máximo ~7 envios por segundo |
| base em isolate | importar um talhão grande não congela a tela |
| mapa 2D refeito no máximo 1×/s | a cabine não redesenha a imagem a cada GPS |
| VT só com `setState` se o JSON mudou | a tela parada não custa nada |
